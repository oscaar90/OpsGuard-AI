// El hallazgo honesto (y por qué es lo mejor del lab)

Esto es lo que el clúster te dijo y tu resumen mental no: OpsGuard no es un servicio.

El Ingress devuelve HTTP 502 — a propósito

OpsGuard es una CLI batch: escanea un diff, imprime el veredicto y termina. No escucha en ningún puerto. Así que el Service y el Ingress enrutan hacia un backend que no existe. Verificado:

curl al Ingress — comprobar el 502
curl -s -o /dev/null -w "HTTP %{http_code}\n" \
  -H "Host: opsguard.localhost" http://192.168.1.51/

# respuesta:
HTTP 502   # Traefik y el Service resuelven; no hay nada escuchando detrás

Traducción para entrevista: el primitivo K8s correcto para OpsGuard es un Job / CronJob disparado por CI, no un Deployment con Service e Ingress. El Secret (API key aislada, consumida por envFrom) y el Job son defendibles al 100%. El Service e Ingress se dejaron escritos como práctica de manifiestos, con el 502 a la vista y anotado en los propios ficheros. Nada maquillado.

// Cómo fue, paso a paso

La bitácora del diario. Incluye los dos tropiezos, porque replicar sin ellos te haría chocar igual.

  • 07:59 — cluster
    k3s ya estaba sano; kubectl no leía el kubeconfig
    Nodo Ready desde hace 91 días. /etc/rancher/k3s/k3s.yaml es 0600 root, y k3s exporta un KUBECONFIG global que apunta ahí. Se copió a ~/.kube/config con permisos de usuario.
  • 08:00 — image
    Build con Docker, import a containerd
    k3s usa containerd, no el daemon de Docker: una imagen de docker build no es visible sin importarla con k3s ctr images import.
  • 08:05 — tropiezo 1
    click 8.3.1 rompe el parseo de opciones de typer 0.9.4
    opsguard --help y --path X revientan. Pero la Action usa opsguard scan sin opciones y ese camino funciona. No se tocó: es deuda del repo, no del lab.
  • 08:08 — tropiezo 2
    Gate 1 necesita un HEAD
    Escanea líneas añadidas de git diff HEAD. Un repo recién iniciado sin commit no tiene HEAD → falla. Solución: commitear una línea base limpia y luego meter el secreto.
  • 08:12 — manifests
    Namespace, Secret, Deployment, Service, Ingress aplicados
    Runner Running, readiness OK, Secret cableado por envFrom (verificado en el pod).
  • 08:15 — scan
    Escaneo real dentro del clúster → BLOCK
    El Job caza 2 claves AWS y sale con exit≠0. El Job queda Failed: eso es fail-closed correcto, no un fallo.

$ Replicar desde cero

Si borras todo (kubectl delete ns opsguard) y quieres reconstruirlo, esto es el camino completo. Ejecuta desde projects/ops_guard/.

0 · kubectl operativo sin sudo (una vez)

kubeconfig de usuario
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown $USER:$USER ~/.kube/config && chmod 600 ~/.kube/config
export KUBECONFIG=$HOME/.kube/config   # k3s exporta uno global que hay que pisar
kubectl get nodes

1 · construir la imagen e importarla a k3s

build + save + import
docker build -t opsguard:lab .
docker save opsguard:lab -o /tmp/opsguard-lab.tar
sudo k3s ctr images import /tmp/opsguard-lab.tar
sudo k3s ctr images ls | grep opsguard   # verificar que está en containerd

2 · namespace y Secret (la key nunca va en git)

namespace + secret imperativo
kubectl apply -f deploy/k8s/00-namespace.yaml

# Secret real, fuera de git. Gate 1 no usa la key (valor dummy vale).
# Para usar Gate 2 (LLM), pon aquí tu OPENROUTER_API_KEY real.
kubectl -n opsguard create secret generic opsguard-secrets \
  --from-literal=OPENROUTER_API_KEY='dummy-not-used-by-gate1'

3 · desplegar y verificar

apply runner + service + ingress
kubectl apply -f deploy/k8s/20-deployment.yaml \
              -f deploy/k8s/30-service.yaml \
              -f deploy/k8s/40-ingress.yaml
kubectl -n opsguard rollout status deploy/opsguard-runner
kubectl -n opsguard get pods,svc,ingress

4 · lanzar el escaneo real (el Job)

configmap + job + logs
kubectl apply -f deploy/k8s/45-configmap-scan.yaml \
              -f deploy/k8s/50-job-scan.yaml

# el Job termina en Failed a propósito (BLOCK = exit≠0 = fail-closed)
kubectl -n opsguard wait --for=condition=failed job/opsguard-scan --timeout=60s
kubectl -n opsguard logs job/opsguard-scan
